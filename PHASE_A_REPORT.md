# NETLAB — PHASE A DECOUPLING COMPLETE

## Domain State Extracted
The `SimulationStore` (`useSimulationStore.ts`) has been successfully stripped of its previous UI and screen-state responsibilities. It now exclusively governs the pure simulation domain and engine orchestration. The following properties and logic remain strictly in the Domain Store:
- `engine` (instance of `SimulationEngine`)
- `devices` (array of `Device` network nodes)
- `links` (array of `Link` topology connections)
- `currentTick` (simulation time tracker)
- `eventHistory` (array of recorded `SimulationEvent` objects)
- `activePackets` (array of in-transit `ActivePacket` data)
- Domain orchestrator actions (`loadBasicLab`, `loadBrokenGatewayLab`, `loadRandomScenario`, `stepForward`, `reset`, `addDevice`, `addLink`, `updateDevicePosition`)
- Protocol event handlers mapping Intents to Packets (via `registerEngineHandlers`)

## UI State Extracted
A brand-new isolated boundary, `WorkspaceStore` (`useWorkspaceStore.ts`), was created to capture all user-facing interface toggles, view selections, and overlay states. The following properties were migrated:
- `currentView` (`'LAB'` vs `'PRACTICE'`)
- `mode` (`'SIMULATE'` vs `'EDIT'`)
- `selectedPacketId`
- `pendingLinkSourceId`
- `activeTerminalDeviceId`
- `selectedDeviceIdForConfig`
- `diagnosticReport` (Generated by `NetworkDoctor`, managed here for UI display)
- Prediction tools UI state (`isPredictionModeEnabled`, `pendingPrediction`, `activePrediction`, `predictionResult`)
- Gamification state (`isLabResolved`)

## React Boundaries Cleaned
All React components that previously mixed UI interaction and Engine tracking through the god-object `useSimulationStore` have been surgically refactored to pull specifically from the `WorkspaceStore` when rendering conditional UI. Components updated:
- `App.tsx` (Reads `currentView` from Workspace)
- `AppHeader.tsx` (Reads/writes prediction mode, modes, and triggers diagnostics from Workspace)
- `SimulationControls.tsx` (Reads `mode` from Workspace)
- `DeviceConfigPanel.tsx` (Reads active configuration device from Workspace)
- `NetworkDoctorPanel.tsx` (Reads report output from Workspace)
- `PacketInspector.tsx` (Reads active packet selection from Workspace)
- `Terminal.tsx` (Reads active terminal device from Workspace)
- `PredictionModal.tsx` & `PredictionResultModal.tsx` (Isolated to Workspace modal states)
- `TopologyView.tsx`, `DeviceNode.tsx`, `PacketNode.tsx` (Read modes, selection intents, and UI interactions from Workspace, falling back to SimulationStore ONLY for node rendering).

## Hardcoded Actions Identified & Relocated
Several debug/test actions were previously hardcoded directly inside `useSimulationStore` mixed alongside viewport flags. These test triggers have been properly isolated:
- `sendPing(sourceId, targetHostname)`: Still triggers an `APP_PING_INTENT` event directly onto the engine queue, but no longer relies on internal state flags to block itself; it cleanly references `WorkspaceStore.isPredictionModeEnabled` to route intent logic.
- `requestDHCP(deviceId)`: Maintained as an application intent mapped to the engine layer without interacting with the UI view layer.
- `injectFault('LINK_DOWN' | 'BAD_GATEWAY')`: Remaining in the SimulationStore as explicit scenario orchestration endpoints (used for testing).
- `runDiagnostics()`: The orchestration wrapper that parses `evaluateNetworkHealth` was moved entirely into `useWorkspaceStore`, evaluating the current snapshot of the pure Engine and mapping the report directly to the UI overlay state.
